# Health OS (учебная версия) — правила для агента

Этот файл читают и Claude Code (CLAUDE.md), и Codex (AGENTS.md); содержимое одинаковое.

## Что это
Личная медкарта: анализы и заключения врачей превращены в записи с датами, по ним строятся
графики, а Telegram-бот отвечает на вопросы и напоминает о пересдаче. Данные — про ВЫМЫШЛЕННОГО
пациента. Работает на стандартном Python 3.10+, без сторонних библиотек; модель — OpenAI по ключу.

## Где что лежит
- `medcard/<год>/` — анализы: оригинал (PDF, скрин, фото) и рядом `.md` с разбором.
- `medcard/визиты к врачам/` — заключения врачей: фото и разбор.
- `new-documents/` — новые документы для урока, ещё не добавленные в медкарту.
- `data/health-record.json` — главный машинный свод: профиль, показатели с историей, визиты,
  напоминания, короткий статус. Страница и бот читают только его.
- `data/garmin.json` — данные часов за 90 дней и личные нормы.
- `app/` — код: `markers.py` справочник показателей, `medcard.py` приём документов, `ask.py` ответы,
  `bot.py` Telegram-бот и напоминания, `web.py` страница под паролем, `llm.py` вызов OpenAI.
- `dashboard/` — страница медкарты; пересборка: `python3 dashboard/build.py`.
- `run.py` — запуск и проверка; `.env` — ключи и настройки (не в git, пример — `.env.example`).
- `dev/` — генераторы учебных данных, к работе системы не относятся.

## Учебный сервер (на уроке страница и бот работают ТАМ, а не на ноутбуке)
На воркшопе у каждого участника есть свой аккаунт на учебном сервере: номер N (2…15) и пароль
`os86NN` (os + порт: участник 7 → `user7` / `os8607`). Там уже стоит этот проект, ключ OpenAI и
всё нужное. Человек открывает свою страницу `http://2.31.18.229:86NN` (пароль тот же).
Ноутбук — только место, где ты правишь код; Python на ноутбуке не нужен, не ставь его.

- **Номер и пароль** храни в `.env` проекта: `WORKSHOP_USER=user7`, `WORKSHOP_PASSWORD=os8607`.
  Если их там нет — спроси у человека номер.
- **«Залей на сервер»** — из корня проекта упакуй его без `.git` и копии диска КТ (она уже на сервере):
  `tar -czf ../health-os.tar.gz --exclude=.git --exclude=ct-disk-copy .` затем
  `curl -u user7:os8607 --data-binary @../health-os.tar.gz http://2.31.18.229:8700/deploy`.
  `.env` в архиве — намеренно: сервер берёт из него только токен бота, остальное игнорирует.
  Адреса с `?` всегда бери в кавычки, имена файлов с пробелами и русскими буквами — тоже.
  На Windows те же команды есть встроенные: `tar.exe` и `curl.exe` (в PowerShell пиши именно
  `curl.exe`, просто `curl` там — другая команда). Покажи человеку ответ сервера и ссылку на страницу.
  Сервер заменяет КОД; данные медкарты (`data/`, `medcard/`) остаются серверные. Из `.env`
  берётся только `TELEGRAM_BOT_TOKEN`: если он есть и в коде есть бот — сервер сам запускает бота.
- **Добавить документ в медкарту** — только на сервере (там живут данные, их же меняет бот):
  `curl -u user7:os8607 "http://2.31.18.229:8700/run?cmd=add" --data-urlencode "file=new-documents/<имя файла>"`
  (несколько скринов одного анализа — одна дата и одна лаборатория в имени — передавай
  несколькими `--data-urlencode "file=…"` в ОДНОЙ команде; остальные документы — по одному).
  Папка `new-documents` на сервере уже есть. Свои новые файлы сначала положи в проект и залей.
- **Кадры КТ с диска:** `curl -u … "http://2.31.18.229:8700/run?cmd=ct" --data-urlencode "file=ct-disk-copy"`.
  **Вопрос по медкарте:** `curl -u … "http://2.31.18.229:8700/run?cmd=ask" --data-urlencode "q=<вопрос>"`.
  **Проверка настроек:** `curl -u … -X POST "http://2.31.18.229:8700/run?cmd=check"`.
- **Бот** до шага 6 не запущен (`бот: inactive`) — это нормально: его ещё нет в коде.
- **Что запущено и ошибки:** `curl -u user7:os8607 http://2.31.18.229:8700/status`.
- **Забрать серверные данные себе** (чтобы читать свод локально):
  `curl -u user7:os8607 -o data.tar.gz http://2.31.18.229:8700/data` и распаковать в проект.
- **«Подключи готовое решение шага N»** — скопируй содержимое `steps/NN-*/solution/` поверх корня
  проекта (структура папок внутри solution та же, что в проекте; свои правки в тех же файлах
  при этом заменятся — предупреди человека, если они были), затем залей на сервер.

## Частые задачи без учебного сервера (когда Python есть на этой машине; на уроке — раздел выше)
- **Добавить анализ или заключение:** `python3 run.py add "<файл>" ["<файл>"…]`. Несколько скринов
  одного анализа передавай одной командой. Покажи человеку ответ команды.
- **Ответить на вопрос по медкарте:** `python3 run.py ask "<вопрос>"` или прочитай свод сам.
- **Проверить настройки:** `python3 run.py check`.
- **Запустить страницу и бота:** `python3 run.py` (держит процесс; для фона — см. README).
- **Новый показатель в справочник:** добавь его в `app/markers.py` по образцу (названия на трёх
  языках, единицы, норма, коэффициент mg/dl, если есть).

## Шаги урока
- В `steps/` лежат шаги урока: в каждом `prompts.md` (фразы, с которых начать), `spec.md` (всё, что
  собрано за десятки итераций) и `solution/` (готовое решение).
- **«Подключи готовое решение шага N»** — скопируй `steps/NN-*/solution/` поверх проекта (или
  `python3 run.py step N`, если есть Python) и залей на сервер. Данные это не трогает.
- **«Сделай по спеке шага N»** — прочитай `steps/NN-*/spec.md` и сделай всё по нему, потом залей на сервер (сервер сам пересоберёт страницу).

## Правила
- Единицы — СИ, как в Беларуси и России; mg/dl пересчитывает код по справочнику, оригинал — в скобках.
- Никогда не выдумывай значения. Не видно цифру — так и скажи.
- Не ставь диагнозов и не назначай лечение — только факты из документов и сравнение с прошлым.
- Ключи из `.env` не печатай и не коммить.
- Ответы человеку — на русском, простыми словами.
